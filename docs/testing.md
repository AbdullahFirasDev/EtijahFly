## سيناريوهات E2E

بوابة الشركات (`apps/partner-portal/e2e`): صفحة دخول بعلامة الشركة و RTL ورفض كلمة مرور خاطئة · الكوكي `httpOnly/Strict` وعدم
وصول JavaScript للتوكن · **رحلة كاملة**: بحث ← عرض تجريبي مُعلَّم ← بيانات المسافر ← حجز مبدئي بـ PNR ← إصدار ← ظهور رقم التذكرة
`000-…` والتذكرة الإلكترونية · المحاسب يرى المالية ولا يرى البحث (403) · رفض مسارات الإدارة عبر بوابة الشركات.

لوحة الإدارة (`apps/admin-portal/e2e`): إعادة التوجيه لصفحة الدخول · رفض دخول مستخدم شركة · لوحة المنصة والشركات المزروعة ·
**اعتماد دفعة** أرسلها محاسب شركة عبر الـ API · موظف المنصة يرى سجل التدقيق وحالة النظام ولا يدير المستخدمين.

## ملاحظات

- اختبارات الباك إند تعمل على قاعدة `etijahfly_test`، و E2E على `etijahfly_e2e`؛ قاعدة التطوير لا تتأثر.
- مسارات الفشل لدى المزود (تغير السعر، رفض الحجز، انقطاع الإصدار، استرداد معلّق…) مغطاة عبر سيناريوهات مزود المحاكاة.
- اختبارات Airlines API الحقيقية اختيارية لأنها تستهلك الحصة المجانية (100 طلب/شهر).
- لم يُختبر الاتصال بـ Supabase السحابي (لا توجد بيانات اعتماد)؛ جرى كل شيء على PostgreSQL 17 محلياً، وهو الإصدار نفسه
  الذي تستخدمه Supabase، وسلوك RLS مع أدوار `anon`/`authenticated` مغطى بالكود الذي يتحقق من وجودها.
