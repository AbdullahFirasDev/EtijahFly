# الأمان والصلاحيات

## المصادقة والجلسات

| الضابط | التنفيذ |
|---|---|
| توكنات Sanctum مرتبطة ببوابة | `portal:partner` / `portal:admin`؛ الوسيط `portal` يرفض أي توكن أو مستخدم من البوابة الأخرى |
| عدم تعريض التوكن للمتصفح | BFF: الكوكي `httpOnly; SameSite=Strict; Secure` (إنتاج) على نطاق البوابة؛ الرد على الدخول لا يحتوي التوكن |
| انتهاء الجلسة | مطلق (8 ساعات) + خمول (120 دقيقة) + حد 10 جلسات لكل مستخدم |
| إلغاء فوري | تعطيل المستخدم أو إيقاف الشركة يحذف كل توكناتهم ويُرفض أي طلب لاحق؛ تغيير كلمة المرور يُنهي الجلسات الأخرى |
| إدارة الجلسات | قائمة الجلسات النشطة (IP، الجهاز، آخر استخدام) وإنهاؤها من الملف الشخصي |
| كلمات المرور | 10 أحرف+ بحروف كبيرة/صغيرة ورقم ورمز؛ فحص التسريبات (HIBP) في الإنتاج؛ bcrypt |
| منع تعداد الحسابات | رسالة موحدة للبريد غير الموجود/الخطأ/البوابة الخاطئة، ونفس الرد لطلب إعادة التعيين |
| تحديد المعدل | الدخول 5/دقيقة/بريد و10/دقيقة/IP؛ إعادة التعيين 3/دقيقة؛ API 240/دقيقة؛ البحث 30/دقيقة |
| الدعوات | توكن عشوائي 64 حرفاً، يُخزّن SHA-256 فقط، صلاحية 72 ساعة، استخدام واحد |

## الصلاحيات (Spatie)

- كتالوج واحد (`PermissionCatalog`) بنطاقين منفصلين: `platform.*` لموظفي المنصة و صلاحيات الشركات.
- لا يمكن منح دور منصة لمستخدم شركة (التحقق في `RoleService`)، والأدوار المخصصة للشركة لا تقبل إلا صلاحيات الشركات،
  واسمها مقيّد بالشركة (`t{id}:slug`) فلا تراه أو تسنده شركة أخرى.
- `User::scopedPermissionNames()` يتجاهل أي صلاحية خارج نطاق المستخدم (دفاع إضافي).
- يمنع: تعطيل/إزالة آخر مالك للشركة، تغيير حالة الحساب الذاتي، منح النفس أدواراً إضافية.

| الدور | أبرز الصلاحيات |
|---|---|
| Super Admin | كل صلاحيات المنصة |
| Platform Staff | الشركات (قراءة)، الحجوزات وإدارتها، طلب التسويات، التدقيق، حالة النظام |
| Platform Finance | الدفعات، اعتماد التسويات، الحدود الائتمانية، أسعار الصرف، التقارير |
| Company Owner | كل صلاحيات الشركة (الموظفون، الأدوار، العلامة، المالية، الحجوزات) |
| Booking Agent | البحث، الحجز، الإصدار، الإلغاء، طلب الاسترداد، المسافرون، المستندات (حجوزاته فقط) |
| Accountant | المالية، الدفعات، الفواتير، العمولات، التقارير، عرض كل الحجوزات (دون حجز أو إصدار) |

## عزل البيانات

- نطاق `tenant_id` على مستوى النموذج + ضبط السياق قبل ربط المسارات ⇒ سجل شركة أخرى = `404`.
- رفض الكتابة على سجل شركة أخرى حتى لو حاول الكود ذلك (`LogicException`).
- PostgreSQL: RLS مفعّل على **كل** الجداول مع سحب صلاحيات `anon`/`authenticated` (Supabase Data API لا يرى شيئاً).
  اختبار آلي يفشل إذا أُضيف جدول دون RLS.
- الحقول الحساسة: أرقام الجوازات مشفرة (`encrypted` cast) ولا تُعاد إلا مقنّعة (`****5678`)، إلا عند اختيار مسافر محفوظ لتعبئة نموذج.
- البيانات الداخلية (تكلفة المورد، الهامش، الربح) لا تُعاد إلا في مسارات الإدارة.

## حماية الطلبات

| التهديد | الحماية |
|---|---|
| CSRF | كوكي `SameSite=Strict` + فحص `Origin` لكل طلب غير آمن في خادم البوابة؛ الـ API نفسه بلا كوكيز |
| CORS | قائمة أصول محددة (`CORS_ALLOWED_ORIGINS`) بلا credentials |
| الوصول المباشر بين البوابات | قائمة مسارات مسموحة في كل BFF (لا `admin/*` من بوابة الشركات والعكس) + مسار عبور مرفوض (`..`, `//`) |
| تزوير IP | `TRUSTED_PROXIES` افتراضياً للشبكات الخاصة فقط |
| رفع الملفات | الشعار PNG/JPG/WEBP فقط بفحص المحتوى الفعلي (لا SVG)، 1MB؛ الإيصالات PDF/صور 5MB؛ كل الحاويات خاصة |
| تكرار العمليات المالية | `Idempotency-Key` + مفاتيح فريدة + أقفال صفوف |
| الترويسات | `nosniff`, `X-Frame-Options: DENY`, `Referrer-Policy`, `CSP` للـ API، `HSTS` في الإنتاج، `Cache-Control: no-store` |
| الأسرار | في بيئة الخادم فقط (`.env` مستثنى من Git)؛ لوحة الإدارة تعرض "مهيأ/غير مهيأ" ولا تعرض المفاتيح |
| تشغيل XAMPP | `.htaccess` في الجذر يمنع Apache من تقديم أي ملف من المستودع |

## سجل التدقيق

يُسجّل: الدخول والفشل والحظر، الخروج، إعادة التعيين، الدعوات وقبولها، تغيير الأدوار والحالة، الأدوار المخصصة،
إنشاء/تعديل/إيقاف الشركات، العلامة التجارية، الحدود الائتمانية وتجميد الحسابات، قواعد التسعير، أسعار الصرف،
المزودين، الحجز والخصم والإصدار والإلغاء والاسترداد، الدفعات والتسويات، المسافرين.
كل سجل: الفاعل، الشركة، العنصر، القيم قبل/بعد، IP، المتصفح، معرّف الطلب. القيم المطابقة لـ
`password|secret|token|api_key|authorization|cookie|document_number|passport|card` تُستبدل بـ `[redacted]`.
الجدول غير قابل للتعديل أو الحذف (مشغل قاعدة بيانات).
