# النظام المالي

## المبادئ

- **قيد مزدوج**: كل عملية مالية = معاملة (`ledger_transactions`) بسطور (`ledger_entries`) يتساوى فيها المدين والدائن،
  بعملة واحدة. `LedgerService` هو الكاتب الوحيد ويرفض أي معاملة غير متوازنة أو خارج معاملة قاعدة بيانات.
- **لا حذف ولا تعديل**: مشغلات PostgreSQL ترفض `UPDATE/DELETE/TRUNCATE` على جداول القيود وسجل التدقيق والسجل
  الزمني للحجز. التصحيح يكون **بقيد عكسي** (`reverses_transaction_id` فريد ⇒ لا يُعكس القيد مرتين) أو **تسوية معتمدة**.
- **أرصدة متزامنة**: `ledger_accounts.balance` يُحدَّث تحت قفل الصف (`SELECT … FOR UPDATE` بترتيب المعرّف لتجنب الجمود)
  ويُحفظ `balance_after` مع كل سطر، فيُبنى كشف الحساب مباشرة.
- **دقة عشرية**: كل الحسابات بـ `brick/math` (`Money`)، لا أعداد عشرية عائمة. منزلتان عشريتان لكل العملات.
- **منع التكرار**: `idempotency_key` فريد على المعاملات (`booking:{id}:charge`، `payment:{id}`، `refund:{id}` …).

## الحسابات

| الرمز | المالك | الطبيعة | الغرض |
|---|---|---|---|
| `AGENCY_WALLET` | كل شركة (لكل عملة) | دائن (التزام على المنصة) | رصيد الشركة المدفوع مسبقاً؛ يسمح بالسالب حتى الحد الائتماني |
| `SUPPLIER_PAYABLE` | المنصة | دائن | المستحق لمزودي الحجز |
| `MARKUP_REVENUE` | المنصة | دائن | إيراد الهامش |
| `COMMISSION_EXPENSE` | المنصة | مدين | عمولات الشركات |
| `REFUND_FEE_REVENUE` | المنصة | دائن | رسوم الاسترداد (اختيارية، `platform.finance.refund_fee`) |
| `CASH_BANK` | المنصة | مدين | النقد والحسابات المصرفية |
| `ADJUSTMENTS` | المنصة | مدين | الطرف المقابل للتسويات اليدوية |

**المتاح للحجز** = الرصيد + الحد الائتماني. يُمنع الحجز المبدئي والإصدار إذا كان صافي التكلفة أكبر من المتاح،
أو كان الحساب مجمّداً. الفحص النهائي يتم تحت قفل الحساب لحظة الخصم.

## التسعير والعمولة (منع الاحتساب المزدوج)

```text
supplier_total  = سعر المورد (أساسي + ضرائب)
markup          = قاعدة الهامش (نسبة من supplier_total أو مبلغ ثابت)
sale_total      = supplier_total + markup          ← السعر الذي تراه الشركة ويُفوتر
commission      = قاعدة العمولة (نسبة من السعر الأساسي أو supplier_total أو مبلغ ثابت) ≤ markup
agency_net      = sale_total − commission           ← صافي ما يُخصم من الشركة
platform_profit = markup − commission ≥ 0
```

- قاعدة **هامش واحدة** وقاعدة **عمولة واحدة** فقط لكل عرض: الأكثر تحديداً (الشركة > شركة الطيران > المسار > الدرجة …) ثم الأعلى أولوية.
- الهامش لا يُحسب على العمولة، والعمولة لا تُحسب على الهامش. الحد الأدنى/الأعلى لكل قاعدة.
- الأسعار تُعاد حسابها عند إعادة التسعير قبل الحجز، وتُحفظ القواعد المطبقة داخل الحجز (`pricing`).

## العملات وأسعار الصرف

IQD و USD. أسعار الصرف سجل تاريخي (`exchange_rates`) — كل سعر جديد سجل جديد، ويُستخدم الأحدث الساري.
عند الخصم يُحوَّل من عملة العرض إلى عملة حساب الشركة ويُحفظ `fx_rate` على الحجز والمعاملة.
**الاسترداد يستخدم سعر الحجز الأصلي** فلا تتحمل الشركة فروق الصرف. إن لم يوجد سعر معتمد يُرفض الحجز (`EXCHANGE_RATE_MISSING`).
(قيد معروف: أرباح/خسائر فروق الصرف للمنصة مقابل المورد لا تُسجّل بعد في حساب مستقل.)

## القيود لكل عملية

| العملية | مدين | دائن |
|---|---|---|
| خصم الحجز (عند الإصدار) | محفظة الشركة: sale_total · مصروف العمولة: commission | ذمم المورد: supplier_total · إيراد الهامش: markup · محفظة الشركة: commission |
| فشل الإصدار / إلغاء بعد الخصم | قيد عكسي كامل للمعاملة السابقة + إشعار دائن | |
| استرداد بعد الإصدار | ذمم المورد: المبلغ المسترد من المزود · محفظة الشركة: استرجاع العمولة | محفظة الشركة: المسترد − رسوم المنصة · إيراد الرسوم · مصروف العمولة |
| دفعة معتمدة | النقد/البنك | محفظة الشركة |
| تسوية لصالح الشركة | التسويات | محفظة الشركة |
| تسوية على الشركة | محفظة الشركة | التسويات |

الهامش لا يُرد عند الاسترداد (رسم خدمة)، والعمولة تُسترجع كاملة. الحجز المبدئي **لا يخصم شيئاً**.

## الموافقات المالية

| العملية | الصلاحية | الضوابط |
|---|---|---|
| تسجيل دفعة | `payments.submit` (الشركة) | لا تؤثر على الرصيد حتى الاعتماد؛ إثبات PDF/صورة في تخزين خاص |
| اعتماد/رفض دفعة | `platform.payments.review` | لا يعتمدها من سجّلها؛ مرة واحدة فقط |
| طلب تسوية | `platform.adjustments.request` | سبب إلزامي (10 أحرف على الأقل) |
| اعتماد تسوية | `platform.adjustments.approve` | **أربع أعين**: يجب أن يكون مستخدماً غير مقدم الطلب |
| الحد الائتماني / تجميد الحساب | `platform.credit.manage` | سبب إلزامي، مسجّل في سجل التدقيق (القيمة قبل/بعد) |
| استرداد يدوي (خارج النظام) | `platform.bookings.manage` | مرجع تأكيد الطيران/BSP إلزامي، لا يتجاوز سعر المورد |

## الفواتير والتقارير

- فاتورة `INV-YYYY-NNNNNN` عند كل خصم، وإشعار دائن `CN-YYYY-NNNNNN` عند العكس أو الاسترداد (ترقيم متسلسل بلا فجوات).
- كشف الحساب للشركة (JSON/CSV) وللإدارة لكل حساب، مع رصيد افتتاحي وختامي.
- تقارير: المبيعات والتكلفة والهامش والعمولة والربح **لكل عملة على حدة**، الحجوزات حسب الحالة، أكثر شركات الطيران،
  المبيعات اليومية، العمولات (مع الاسترجاع)، والأرصدة المستحقة لكل شركة.
